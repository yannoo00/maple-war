# unit-editor — 유닛 데이터 입력 툴

`RootDesk/MyDesk/Data/UnitTable.csv`(+ `StageWaveTable.csv`, `StageTable.csv`의 LoopPool)에 몬스터 / 설치물 / 스킬을 넣고 고치는 툴. 서버와 CLI는 Node만 있으면 되고, 브라우저 화면(React)은 한 번 빌드해야 한다.

```
cd tools/unit-editor/web && npm install && npm run build   # 처음 한 번, 화면 코드를 고친 뒤에도
```

사람과 Claude가 **같은 검증·저장 코드**를 쓴다.

| 입구 | 누가 | 실행 |
|---|---|---|
| 브라우저 편집기 | 사람 | `node tools/unit-editor/server.cjs` → http://localhost:3456 이 열린다 |
| CLI | Claude (또는 스크립트) | `node tools/unit-editor/cli.cjs <명령>` — 명령 목록은 인자 없이 실행 |
| Claude 스킬 | Claude | `.claude/skills/add-unit/SKILL.md` — "유닛 추가해줘"라고 하면 이 절차로 CLI를 쓴다 |

## 파일

- `schema.cjs` — 열 정의, 종류별 필수/허용 칸, enum, 기본값, 도움말. **규칙을 바꾸려면 여기만 고친다.**
- `unitdata.cjs` — CSV 읽기/쓰기(UTF-8 BOM + CRLF 유지), 검증, 추가/수정/삭제, 시간표·반복 풀 반영, 아군/적 파생 상태.
- `cli.cjs`, `server.cjs` — 두 입구. 서버는 `dist/`(빌드 결과)와 JSON API를 서빙한다.
- `web/` — 브라우저 화면(React + Vite). 화면 개발은 `node server.cjs --no-open`을 켜 두고 `web/`에서 `npm run dev`.
  - `src/modes.js` — 유닛/스테이지/효과가 다른 점(초안 만들기, 저장 문구, 삭제 확인)만 모아 둔 설정. 세 편집기가 같은 저장·검사·삭제 흐름을 쓴다.
  - `src/App.jsx` — 상태와 저장/검사/삭제 흐름. `src/Sidebar.jsx` 목록, `src/Field.jsx` 스키마 기반 입력칸, `src/forms/*` 모드별 폼.

## 유닛 요약 표

유닛 모드 상단의 `[편집 | 표]`에서 "표"를 고르면 몬스터/설치물/스킬을 한 표(등급·마나·공격력·체력·공격타입)로 보면서 바로 고치고 "모두 저장"으로 한 번에 저장한다. 저장은 유닛 편집과 같은 검증을 거치며, 오류는 해당 행 아래에 표시된다. 새 유닛의 종류는 폼의 "종류" 칸에서 고른다(복제 기능은 없음).

## 기지 편집

기지(베이스캠프)는 유닛 표(`UnitTable`)의 `Kind = base` 행이다. 유닛 모드에서 종류를 "기지"로 고르면 기지 칸 그룹이 열린다: 시작 마나·마나 최대/회복 배율, 기지 스킬(스킬 행의 id, 능동/패시브, 쿨타임), 월드 상품 ID(빈칸 = 판매 안 함), 적 전용. 기본 기지는 `base`(스타터), 나머지는 상품을 등록해 `ProductId`를 적으면 상점 카드에서 구매할 수 있다. 영구 강화 수치는 `BaseLevelTable.csv`(레벨별 HP 배율·마나 강화 할인·메소 비용)를 직접 고친다. 스테이지의 적 기지는 스테이지 편집의 "적 기지" 칸.

## 스테이지 편집

상단 "스테이지" 모드에서 `StageTable.csv`(스테이지 속성 + 반복 풀)와 `StageWaveTable.csv`(시간표)를 **스테이지 단위**로 편집한다.

- 시간표: "몇 초에 어떤 유닛을 몇 레벨로" 행 목록. 위에 타임라인이 그려지고 저장 시 시간순으로 정렬된다.
- 반복 풀: 시간표가 끝난 뒤 무작위로 계속 뽑는 유닛 목록. 같은 유닛을 여러 번 넣으면 가중치.
- 유닛 모드의 "스테이지 등장" 칸은 읽기 전용이고 "스테이지 열기" 버튼으로 넘어간다. 유닛 저장은 스테이지 파일을 건드리지 않는다.
- CSV에 스키마가 모르는 열이 있으면(다른 세션이 코드로 추가한 열) "기타 열"로 보여 주고 그대로 저장한다.

## 효과 편집

효과(`EffectTable`) 한 행은 **수치**만 정한다: 지속 시간, 세기, `Applies`(target = 적에게 거는 효과 / self = 자신의 특성 / both), 아이콘. 확률 같은 적용 조건은 효과가 아니라 **몬스터·설치물이 가진 규칙**이다.

유닛의 규칙은 `UnitEffectTable.csv`(한 유닛에 여러 줄)에 저장되고, 유닛 편집 화면의 "효과 규칙" 표에서 고친다(시간표처럼 유닛 저장과 함께 저장). 한 줄 = (효과, 시점, 대상, 확률, 지속·세기 덮어쓰기).

| 시점 | 대상 | 의미 |
|---|---|---|
| `on_hit` 공격 시 | `target` | 이 유닛의 공격이 적(몬스터)에게 피해를 줄 때 줄마다 정한 확률(%)로 맞은 적에게 건다 |
| `always` 항상 | `self` | 생성될 때(풀에서 다시 꺼낼 때도) 자신에게 건다. 확률 없음, 사는 동안 지속(지속 시간 칸 무시) |

효과의 `Applies`와 맞지 않는 규칙은 저장이 막힌다. 속성(`Attribute`)은 효과 규칙에는 쓰이지 않고 기본 공격 상성에만 쓰인다(아래 "속성 상성"). 지속·세기를 비우면 효과 표의 값을 쓴다. `curse`의 세기는 공격력 감소 %(50 = 절반)다.

상단 "효과" 모드에서 `EffectTable.csv`를 편집한다. 효과 ID가 곧 코드(`Battle/BattleEffects.mlua`의 등록부) 항목의 이름이라서, 코드에 없는 ID를 저장하면 **미구현 · 설명만 저장**으로 표시된다. 그 상태로 저장해 두고, 화면에 뜨는 요청 글을 복사해 Claude 세션에 붙이면 Claude가 메모의 설명대로 구현한다(절차는 `.claude/skills/add-unit/SKILL.md`). 구현된 효과 목록은 코드에서 자동으로 읽으므로 구현이 끝나면 배지가 "구현됨"으로 바뀐다.

### 속성 상성

몬스터의 `Attribute`는 기본 공격 피해 배율을 정한다(`Battle/BattleConfig.mlua`의 `GetAttributeRate`).

- 유리한 상대에게 피해 **+20%**(전투 설정 `AttributeBonus` = 0.2). 불리한 쪽의 감소는 없다.
- 빛 ↔ 어둠: 서로에게 유리.
- 바람 → 물 → 화염 → 땅 → 바람: 화살표 앞이 뒤에 유리.
- 유닛의 기본 공격(`attack`)에만 적용된다. 스킬·독 등 다른 피해에는 없다.
- 속성이 없는 유닛(건물·기지, 빈칸인 몬스터)은 보너스를 주지도 받지도 않는다.

## 스킬

스킬이 하는 일은 코드(`Battle/BattleSkills.mlua`의 스킬 ID별 항목)이고, 수치만 표에 있다: `SkillDamage` / `SkillRadius` / `SkillHitDelay` / `SkillValue1`·`SkillValue2`(스킬마다 뜻이 다름; 저장하면 그 스킬의 뜻이 안내로 나온다). 코드에 없는 스킬은 #Memo를 스펙으로 적어 저장해 두고 Claude에게 구현을 요청한다.

## 소환의 돌 편집

상단 "소환의 돌" 모드에서 `ChestTable.csv`(소환의 돌 = 등급별 뽑기)를 편집한다. 데이터 코드는 `chestdata.cjs`, CLI는 `cli.cjs chest …`.

- **카드 획득량**: `Cards` = 돌 하나에서 나오는 카드 장수.
- **확률**: `Chance*` = 카드 한 장마다 굴리는 등급 확률(%). **합계가 100%여야 저장된다.** 아래 표에 돌 하나당 기대 장수와 그 등급의 카드 유닛 수가 나오고, 카드 유닛이 없는 등급은 한 단계 낮은 등급으로 나온다는 경고가 뜬다.
- `Guarantee` = 첫 장 보장 등급, `PriceMeso` = 상점 가격(0 = 판매 안 함), `Rarity` = 돌의 등급(테두리 색), `IconRuid` = 이 돌만 쓸 아이콘(빈칸 = `BattleConfig.SummonStoneIconRuid` 기본 아이콘).
- 스테이지 보상(`StageTable.RewardChest`)이 쓰는 돌은 목록에 "보상" 배지가 붙는다. 지우면 그 보상 칸이 비워진다.

## RUID 미리보기

RUID 칸에 32자리 값을 넣으면 공개 리소스 API(`maplestoryworlds-resourcesearch-new.nexon.com`)에서 타입·이름·썸네일(GIF/PNG)을 가져와 칸 아래에 보여 준다. 목록의 작은 그림은 stand 클립(스킬은 범위 이펙트)이다. 인터넷이 없으면 미리보기만 비고 저장은 된다.

## 스킬 효과음

스킬에는 `SkillSoundRuid`(스킬을 쓸 때 재생되는 소리)와 `SkillSoundDelay`(시전 후 몇 초에 재생할지, 빈칸 = 이펙트와 동시)를 둘 수 있다. 소리 RUID를 넣으면 칸 아래에 **재생기**가 뜬다(길이·형식·설명 포함). 몬스터의 공격음·피격음·사망음 칸에도 같은 재생기가 뜬다. 소리는 같은 CDN의 ogg를 서버가 전달하는 것을 브라우저가 재생한다(Chrome 권장).

## 이펙트 위치 맞추기

이펙트가 의도보다 위/아래에 보이면 코드를 고치지 말고 위치 칸으로 맞춘다. 칸은 월드 유닛(1 = 100px), 화면에서 보이는 크기 기준이고, 빈칸이면 지금 위치 그대로다.

| 대상 | 칸 | 기본 위치 |
|---|---|---|
| 스킬 이펙트 | `EffectOffsetX` `EffectOffsetY` | 범위 중심에 가로 중앙, **이펙트 프레임 맨 아래가 지면**. 여기에 더한다(Y는 위가 +) |
| 공격 이펙트 | `AttackEffectOffsetX` `AttackEffectOffsetY` `AttackEffectScale` | 유닛에 붙고 **이펙트 피벗이 유닛 발 위치**. X는 앞이 +, Y는 발 기준 위가 +, 크기는 유닛 크기 위에 곱함 |

유닛 편집 화면의 미리보기(스킬 그룹 / 공격 연출 그룹)가 게임과 같은 규칙으로 **투명 프레임**을 그린다(프레임별 피벗은 리소스 API에서 받는다). 숫자를 입력하지 않고 **드래그**로도 맞춘다(파워포인트처럼): 이펙트 안쪽을 끌면 위치, 이펙트 모서리의 흰 사각형을 끌면 크기(반대쪽 모서리 고정), 스킬 미리보기의 붉은 범위 상자 좌우 막대를 끌면 범위(`SkillRadius`). 드래그는 칸의 값을 바꿀 뿐이고 저장은 평소처럼 누른다. 게임 규칙상 범위를 바꾸면 이펙트도 그 폭에 맞춰 커진다.
- 스킬: 붉은 점선 = 실제 피해 범위, 초록 점선·원 = 이펙트가 실제로 그려지는 영역과 무게중심, 비교 몬스터로 크기 감을 본다. "내용물 하단 → 지면" / "내용물 중앙 → 범위 박스 중앙" 버튼이 위치 칸을 자동으로 채운다.
- 공격 이펙트: 몬스터(stand)와 겹쳐 재생한다. "이펙트 내용물 중앙 → 몸 중앙" 버튼이 위치 칸을 채운다.
- 스킬 미리보기의 "▶ 시전 재생"은 이펙트를 한 번 재생하면서 효과음(`SkillSoundDelay`)과 피해 시점(`SkillHitDelay`, 붉은 상자가 번쩍임)을 같은 시간축으로 보여 준다. 프레임 간격은 클립의 실제 속도를 API에서 알 수 없어 가정값(150ms, 조절 가능)이다.
- 영역은 알파 질량의 가장자리 2%를 버리고 계산해서 희미한 입자에 끌려가지 않는다. 자동 값은 출발점이고, 눈으로 확인하고 미세조정한다.
- 미리보기는 엔진이 이펙트를 붙이는 방식(유닛 크기·좌우 반전)을 가정해 그린다. 처음 몇 개는 게임 화면과 대조한다.

## 규칙 요약

- 유닛 하나 = UnitTable 한 행. `.model`은 만들지 않는다(공용 `BattleUnit.model`).
- 적/아군을 정하는 열은 없다. 카드 유닛은 `Starter=1`이면 처음부터 갖고, 아니어도 상자(`ChestTable`)에서 같은 등급의 모든 카드 유닛 중에 나온다(직접 구매 없음). 적 = 시간표(StageWaveTable) 또는 반복 풀(StageTable.LoopPool)에 있음. 툴은 이걸 배지로 보여 준다.
- 종류에 맞지 않는 칸(예: 스킬의 MaxHp)은 비어 있어야 저장된다.
- 군단: 몬스터 행의 `SpawnCount`가 2 이상이면 카드 한 장으로 그만큼 소환된다(첫 마리는 바로, 나머지는 0.25초 간격 — 게임의 `BattleConfig.MultiSpawnInterval`). 단일 몬스터와 군단은 서로 다른 카드이고, 마리당 능력치·RUID는 각 행의 값이다(비슷한 몬스터를 열어 값을 옮겨 적으면 편하다). 비우면 1마리.
- 설치물은 `Speed=0` 고정, `MoveRuid`가 비면 `StandRuid`로 채운다.
- `base` 행과 알 수 없는 열은 그대로 보존한다.

## 저장 후

Maker에서 **refresh**(플레이 중이면 stop 먼저). Maker의 데이터셋 편집기를 열어 둔 채 이 툴로 저장하면 서로 덮어쓸 수 있으니 닫고 쓴다. 되돌리기는 git(`git diff RootDesk/MyDesk/Data/`).
